六个关键设计决策

每一条都对应一个踩过的坑，而不是"看起来很有道理"的空话。

规则优先，模型只是兜底

意图层先走正则与词表打分，命中就 0 次模型调用；不确定先继承上下文，最后才模型兜底。 实测只有 61.1% 的问答真正调用模型，其余（越界 / 未收录 / 需补条件 / 没听懂）走确定性模板。

规则命中通常 <1ms，模型兜底一次要 0.8–1.2 秒——"规则优先"不只是偏好，是实打实的延迟差

回答的依据强度是分层的

每条回答都标明依据：有知识库依据（带来源卡片）/ 通用理解（kb_gap，不展示来源）/ 未收录（kb_miss，如实说不知道）/ 没听懂。玩家一眼能看出"这条回答有多可信"。

无资料支持时 citations: []，绝不填占位来源

未命中 ≠ 能力范围外

题目那句"不要把资料未命中判成能力范围外"，落成了两条零降级路径的独立分支： kb_miss（知识没收录）与 out_of_scope（要求未接入能力）互不转换。

「巅峰赛积分怎么算」如实说未收录，而不是说"这超出我的能力"

评测必须可复核

LLM 评审要逐要点给出原文证据，并逐字校验证据是否真在回答里—— 因为评审模型自己也会编证据。实测把"证据可复核率"从 83.87% 修到 100%。

HTML 报告把回答 / 证据 / 判决并排呈现，可离线抽查

记忆系统：让知识库从真实使用里长出来

两个层次：① 会话画像记住"你常问什么"，让后续回答更贴合关注点；② 跨会话把 "没答上来"的问题按被问次数排序——被反复问到却没收录的，就是知识库最该补的。 这是从"拍脑袋猜用户会问什么"到"从真实流量里长知识库"的闭环。

克制点：只统计"问了什么"、不推断"喜欢玩什么"；≥3 轮才注入、可一键清除

指标的分母都写死

检索命中率只统计检索层（6 例），不掺生成质量；评审耗时单列、不计入 Agent 耗时； 耗时按"调用模型 / 走模板"分开——混在一起会得出"均值小于 P50"这种不可解释的数字。

每个指标都能回答"这个数字是怎么算出来的"

最有含金量的部分：36 项真实缺陷

这些不是"AI 写代码"的炫技，而是"AI 写的代码被我查出来并修掉"的记录，每项都有失败证据。

① S36+ 被归一化成 s36 —— 版本折扣静默失效

S36+ 是王者荣耀的赛季版本号（S=赛季、S36=第36赛季、+=及以后），在本文里只是 单元测试的样本，并非真实知识库内容。归一化把 + 当标点删掉，正则永远匹配不上—— 不报错、不影响其他功能，只有单测断言能抓住这种"看起来正常其实不生效"的缺陷。

修正：版本号改用只保留 + - ~ 的轻量归一化。

② 反野 既是主题词又不在知识库词表 → 检索为空 → 模型编出"插眼"

两个判断互相抵消：是主题词（于是不拼历史），又检不到（于是没材料）。模型没有依据， 就自己引入了同类游戏才有的"插眼"机制。Mock 模式下完全看不出来，接真实模型才暴露。

修正：检索改为"指代句直接补上下文 + 检不到再重试"，并在提示词禁止引入材料外的机制名词。 修正后答复（引用打野职责条目）："被反野按顺序处理——先判断能不能打、再换野区别空转、顺手抓一波补损失；怕的是硬守。"

③ 评测自身也是需要被验证的产出物

T05 被误判违规——回答引用的"主宰一般在暴君之后被争夺"正是知识库原文，是判分规则不可执行； 评审证据可复核率只有 83.87%，逐条抽查后确认不是评审编造，而是评审用「……」跳读、把两段原文拼在一起引用 （这是合法引用），是我的校验器要求"整段连续"才误判。把校验改成按省略号切段后回到 100%。

修正：判分规则量化到可执行 + 新增 judge_note 传达出题意图 + 证据按省略号分段校验。
