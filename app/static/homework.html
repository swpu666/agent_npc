三.1

HTML 使用页面与 Agent 接口

页面：app/static/index.html + app.js；接口：POST /api/chat（app/api/chat.py）。

页面最低要求本项目如何满足
输入问题、发送、展示玩家 / NPC 对话记录 气泡式渲染（renderUser / renderAssistant），展示回答、意图标签、路由状态、四段耗时。
连续追问、清空对话 前端本地维护 turns，按最近 6 轮回传；「清空对话」按钮重置。
等待状态 非流式接口用阶段文案（识别意图 → 检索 → 生成）+ 已等待计时，renderTyping。
失败明确提示 + 重新发送 顶部 notice 提示条 + 「重新发送」按钮，保留已输入内容（lastFailed）。
知识类回答展示来源；无资料不伪造 只渲染后端真实检索到的条目；kb_gap / kb_general / kb_miss / conversation_recall / chitchat / out_of_scope 一律 citations: []。
接口最低要求本项目如何满足
至少一个对话接口，输入含消息与上下文 POST /api/chat 入参 {session_id, message, history}，history 由前端回传、后端截断。
输出含回答 / 意图 / 引用 / 耗时 响应字段 answer / intent / route_state / citations / timings / model / mock / retryable。
支持 3 轮以上，理解「那这个呢」 历史传递 + 上下文检索：只要存在上一轮消息，就把它与当前问句拼接后检索，并按上一轮主题加分。
处理空输入 / 过长 / 失败；可配超时 空 → 400、>1000 字 → 400、模型超时 → 504、4xx → 502、5xx → 502；LLM_TIMEOUT_S 可配。
密钥仅在后端 .env + .gitignore；单测 test_no_api_key_in_frontend_assets 兜底。
三.2

基础游戏知识支持与知识库设计

知识文件：app/data/knowledge/kb_v1.json（33 条 / 5 类主题 / 9 个来源页面），检索：app/agent/retrieval.py。

主题条目数示例内容
地图机制11分路与野区、BUFF 与野怪、暴君 / 主宰刷新与收益、视野草丛、河道
位置职责6对抗路 / 打野 / 中路 / 发育路 / 游走分工
基础操作6补刀与经济、技能连招、回城、装备购买、小地图
对局目标5获胜条件、推塔次序、防御塔机制、投降 / 结算
资源与经济5经济来源构成、经验等级、金币分配

每条知识必含字段：唯一编号 id、主题 topic、正文 content、来源标题 / 链接 / 采集日期（source.title/url/collected_at），以及版本 version（涉及数值必填）。另含 fact_key（语义唯一键，用于版本冲突检测）、source.verified_at（链接校验日期）、source.support（direct / topic 来源强度）、confidence。字段完整性由 kb_lint.py 强制校验。

设计文档需说明的 4 点

① 为什么这样划分知识单元

「一个玩家可独立提出的问题 = 一条知识」，而非按文章切分。理由：检索结果可精确归因（引用到「这一条」）；正文 ≤250 字聚焦单一事实点，便于要点式评测；一条知识一个 fact_key，同键多条即版本冲突，可显式检测。

② 用什么检索方法

规则 + 关键词加权 + BM25 字符 / 词项混合（不引入向量库）。同义词 / 别名 / 简称 / 错别字三张表解决口语鸿沟；多轮追问只要存在上一轮消息就把历史与当前问句拼接后检索；版本折扣 ×0.6 弱化过期条目。

③ 未命中 / 冲突 / 版本不明怎么办

分五种：版本敏感数值的未收录走 kb_miss（如实说不知道，不改判越界）；稳定常识的未收录走 kb_general（用通用理解作答 + 清空来源）；命中但答不了核心诉求走 kb_gap（声明通用理解 + 清空来源）；多版本以较新者为主并注明；confidence: low 追加「仅供参考」。

④ 如何更新与演进

新增跑 kb_lint --check-urls（链接不可达即失败退出码 1）；版本不原地改、新建同 fact_key 条目；规模增大演进路径：JSON+BM25 → SQLite+FTS5 → embedding+RRF 融合，检索接口形状不变。

三.3

基础意图模块（独立可测）

实现：app/agent/intent.py，纯函数 classify(text, history)，无 I/O，模型兜底经依赖注入隔离。

意图行为要求（作业题）本项目判定特征
游戏知识问答检索资料后回答问通用规则 / 事实，不依赖玩家自身局势 → 检索 + 生成，必带来源
游戏情境建议结合条件回答；缺条件适当追问含第一人称局势条件；缺位置 / 阶段 / 英雄 → need_more_info 反问
日常闲聊简短自然，不强制检索社交性表达 / 情绪 / 寒暄 → 简短回应，保持向导身份
能力范围外请求说明限制查战绩 / 段位 / 实时对局、代打、上号等 → 模板回答，不调用模型

多意图优先级：out_of_scope > situational_advice > knowledge_qa > chitchat。 越界最高（涉及未接入能力时顺带回答有编造风险）；闲聊最低（避免把「你好，顺便问下红BUFF」判成闲聊）。

路由状态（不是第五个意图）：need_more_info（补充条件）、kb_miss（缺的是版本敏感数值/算法：如实说不知道）、kb_general（缺材料但属于稳定常识：通用理解作答并标注）、kb_gap（知识库覆盖缺口：英雄级信息 / 动态数据）、unclear_input（没听懂）、conversation_recall（问「我前面问了什么」：复述历史里的提问）。其中「不要因资料未命中就把游戏问题判成能力范围外」是一条硬约束：kb_miss 由检索层产出、out_of_scope 由意图层产出，二者无互相降级路径。

规则 + 模型 + 兜底：① 规则词表打分（0 次模型调用，0.2ms）→ ② 上下文继承（零信号且本轮带承接信号时，继承上一轮路由状态）→ ③ 模型受限分类（temperature=0，仅在前两层都不适用）→ ④ 最终兜底判 knowledge_qa。 注入防护：命中指令模式且不含游戏主题词 → 归 out_of_scope；夹带正常玩法问题则照常按知识问答处理、仅加加固标记。单测 tests/test_intent.py 覆盖四类、优先级、追问、注入、错别字、无意义输入、对话回顾、未命中两档。

三.4

响应效率与基本可观测性

回答耗时主要花在模型生成，本地环节近乎零耗时；每次问答落一条可观测记录。

环节实测说明
意图路由（本地）均值 0.4ms规则命中 0 次模型调用；最大 1.9ms
知识检索（本地）均值 0.3msBM25 + 字段加权，最大 1.3ms
模型生成（含网络）P50 ≈1450ms99.9% 的等待时间在这里（11 例真正调用模型）
模板回答案例<1ms越界 / 未收录 / 需补条件 / 没听懂 共 7 例，走确定性模板

采取的措施：① 按意图 / 路由跳过检索与生成（闲聊不检索；越界 / 未收录 / 需补条件 / 没听懂不调模型）② 规则优先 + 上下文继承占住意图主路径，避免 0.8~1.2s 的模型兜底分类被误触发 ③ 无串行多跳（一次问答至多一次生成）④ 限制上下文（历史 ≤6 轮 + 字符预算、知识 ≤4 条 + 边际裁剪、正文 ≤250 字）⑤ 确定性参数（temperature=0.3、max_tokens=512）⑥ 超时 / 重试可配，超时快速失败返回 retryable: true。

可观测性：响应带四段耗时 timings；每次问答追加一条 logs/requests-*.jsonl（IP / 对话内容 / 意图 / 路由 / 引用 / 耗时 / 错误），配套 /api/logs、/api/logs/stats 与页面「使用记录」抽屉。失败也记录（error 字段标明原因）。隐私：可 LOG_ENABLED=0 关闭、默认截断 2000 字符、本地不提交仓库。

四.A

完整工程 Demo

按评审最短路径即可复现：配置模型 → 启动服务 → 网页连续提问 → 执行离线评测 → 查看报告。

pip install -r requirements.txt → copy .env.example .env（填密钥）→ uvicorn app.main:app --port 8000（打开 http://127.0.0.1:8000/ 连续提问）→ python -m eval.run_eval（报告写入 eval/reports/）。 无密钥可先 MOCK_LLM=1 跑冒烟验证链路（页面有 MOCK 徽标，结果不作为质量结论）。工程含：app/（页面 + 接口 + 意图 + 检索 + 生成）、eval/（测试集 + 评测 + 对话回放 + 报告）、tests/（234 个单测）、知识文件、.env.example、README.md、DESIGN.md。
